## Bugs found and fixed on this branch

1. **BUG-1 (high): `transitionJob` decline left jobs stranded.** `lib/scheduler.ts` `transitionJob` set status `declined`, cleared the assignee, but never returned the job to `scheduled` nor set `needs_attention` — the contracts' two-step. The `/api/dispatcher/*` path (via `transitionDispatcherJob`) was correct; the contracts-specified `/api/jobs/:id/decline` path was not. Fixed `transitionJob` to do declined → scheduled + `needs_attention=true` with both steps audited. QA test added (`tests/qa.test.ts`).
2. **BUG-2 (medium): dashboard hid failures.** `app/dashboard/page.tsx` listed jobs but never surfaced `needs_attention`, broken feeds, or failed reminders — UC10 requires dashboard surfacing. Added an owner-only "Needs attention" section.
3. **BUG-3 (high): 12 contract-specified routes missing.** No `GET/PATCH /api/properties/:id`, no instruction-history endpoint, no checklist-template CRUD (6 routes), no `GET /api/jobs/:id/reminders`, no `POST /api/properties/:id/refresh-listing`. Without them, UC13's history was unwritable and checklist templates uncreatable. All 8 route files added on this branch, following existing auth/RLS patterns (`requireSession`/`requireOwner` + `withUser`).
4. **BUG-4 (low, test-only): timezone time-bomb in `tests/dispatcher.test.ts`.** `isoDatePlus` used UTC dates while the app filters by PT; the test failed 00:00–08:00 UTC daily. Fixed the helper to compute PT dates. (App code was correct.)

## Still open (non-blocking for staging)

1. **Duplicate transition route trees.** `/api/jobs/:id/{confirm,decline,start,complete}` and `/api/dispatcher/jobs/:id/{…}` both exist and now behave identically. Recommend keeping the contracts-specified `/api/jobs/:id/*` tree and retiring `/api/dispatcher/*` in a cleanup PR to avoid future drift.
2. **`package-lock.json` not in the repo** (integration upload limit). Regenerate with `npm install` on deploy. Versions float on `^` ranges until then.
3. **`.github/workflows/ci.yml` not in the repo** (GitHub Apps cannot write workflow files). CI runs via `npm run verify` locally until the file is added manually.
4. **Host dashboard is minimal.** The owner gets job lists + the new alerts section; the rich host UI (calendar view, manual scheduling UI, assignment UI) is a future workstream. All host capabilities exist as APIs.
